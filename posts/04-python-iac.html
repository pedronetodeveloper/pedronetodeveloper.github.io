Python & IaC:
a dupla que faz o simples funcionar

Pedro Neto • 14 jul 2026 • 13 min de leitura

Hora de falar da dupla que me fez, me sentir um dev pela primeira vez.
A Dupla perfeita: Python escreve a lógica, IaC dá o palco. Um sem o outro fica pela metade.

🐍 Python: o código + ⚙️ IaC: o palco
a mentalidade "Python é a porta de entrada mais fácil da programação — e o que pode te tornar um dev mais rápido. E não para no backend: dados, automação, IA, infra... é a língua que quase toda vertente da TI fala."

Python é a linguagem que te deixa focar no problema, não na cerimônia. E o alcance dela é o diferencial: o mesmo Python que faz sua API faz o script de migração, o notebook de análise de dados, o pipeline de IA e a automação de infra. Aprender Python é destravar várias portas da TI de uma vez.

No backend, o framework mais usado do mercado hoje pra APIs novas é o FastAPI — e ele é a cara do Python: pouco código, validação automática e documentação de graça. É com ele que vamos construir o sistema de currículos do RH.

pip install fastapi main.py (FastAPI) ├── POST /usuarios cria candidato ├── GET /usuarios/{id} busca ├── PUT /usuarios/{id} atualiza ├── DELETE /usuarios/{id} remove └── POST /usuarios/{id}/curriculo upload do PDF

CRUD de usuário: o clássico que ensina tudo

Todo sistema começa cadastrando alguém — no nosso caso, o candidato que envia currículo. Olha o CRUD completo, e repara como o FastAPI faz o trabalho chato pra você:

main.py — o CRUD inteiro numa tela

from fastapi import FastAPI, HTTPException
from pydantic import BaseModel

app = FastAPI(title="API de Currículos do RH")

class UsuarioRequest(BaseModel):   # valida a entrada sozinho,
    nome: str                      # tipo o record do post de Java
    email: str

usuarios = {}
proximo_id = 1

@app.post("/usuarios", status_code=201)
def criar_usuario(dados: UsuarioRequest):
    global proximo_id
    if any(u["email"] == dados.email for u in usuarios.values()):
        raise HTTPException(409, f"Email {dados.email} já cadastrado")
    usuario = {"id": proximo_id, **dados.model_dump()}
    usuarios[proximo_id] = usuario
    proximo_id += 1
    return usuario

@app.get("/usuarios/{id_usuario}")
def buscar_usuario(id_usuario: int):
    if id_usuario not in usuarios:
        raise HTTPException(404, "Usuário não encontrado")
    return usuarios[id_usuario]

@app.put("/usuarios/{id_usuario}")
def atualizar_usuario(id_usuario: int, dados: UsuarioRequest):
    if id_usuario not in usuarios:
        raise HTTPException(404, "Usuário não encontrado")
    usuarios[id_usuario].update(dados.model_dump())
    return usuarios[id_usuario]

@app.delete("/usuarios/{id_usuario}", status_code=204)
def deletar_usuario(id_usuario: int):
    if usuarios.pop(id_usuario, None) is None:
        raise HTTPException(404, "Usuário não encontrado")

Repara no que o framework te deu de graça:

  • Validação automática — o UsuarioRequest (Pydantic) rejeita JSON errado antes do seu código rodar. Mesmo espírito do record que valida, lá do post de Java.
  • Conversão de tipo na rota — o id_usuario: int já chega como número. Veio texto? 422 automático.
  • Documentação sem escrever nada — roda fastapi dev main.py e abre /docs: Swagger completo, interativo, de brinde.

Perfil com currículo: upload de arquivo de verdade

O coração do sistema do RH: receber o PDF e montar o perfil do candidato. Com UploadFile, é um endpoint curto:

main.py — continuação: o endpoint de currículo

from datetime import datetime
from pathlib import Path
from fastapi import UploadFile

@app.post("/usuarios/{id_usuario}/curriculo", status_code=201)
async def enviar_curriculo(id_usuario: int, curriculo: UploadFile):
    if id_usuario not in usuarios:
        raise HTTPException(404, "Usuário não encontrado")

    pasta = Path("curriculos")
    pasta.mkdir(exist_ok=True)
    destino = pasta / f"{id_usuario}-{curriculo.filename}"
    destino.write_bytes(await curriculo.read())

    return {
        "usuario": usuarios[id_usuario],
        "curriculo": destino.name,
        "enviado_em": datetime.now().isoformat(),
    }
Confissão: no meu estágio eu fiz tudo isso na mão, sem framework nenhum — REST cru com a biblioteca padrão. Não porque era o jeito certo: era porque a gente nem sabia que existia atalho. Funcionou e me ensinou muito, mas o caminho que eu te recomendo é esse daqui: FastAPI, simples e do jeito que o mercado usa. A história completa está no final do post.
O erro que a gente cometeu no estágio: guardar estado em memória (aquele dict usuarios) e esquecer que servidor reinicia. Um deploy no meio do dia e... cadê os cadastros? Em produção, estado vai pra fora do processo: banco, storage, fila. O dict é ótimo pra aprender e prototipar — e é só isso mesmo.
Quando o Python brilha: APIs com FastAPI, automações do dia a dia, scripts de migração, análise de dados, IA e protótipos que viram demo na sexta-feira. É a linguagem que te faz sentir rápido — 20 linhas resolvem o que parecia precisar de projeto inteiro — e a que mais abre portas se você ainda está escolhendo sua vertente na TI.
a mentalidade "Com IaC eu não preciso me preocupar com servidor nem configurar mil coisas na mão. Escrevo o que preciso, e a infra sobe sozinha."

IaC — Infrastructure as Code — é tratar servidor, função e storage como você trata código: escrito em arquivo, versionado no Git, reproduzível com um comando. E a mágica da dupla é essa: aquela API FastAPI da aba Python sobe em qualquer palco serverless sem mudar uma linha da lógica — só muda o adaptador da borda. (Soou familiar? É o mesmo raciocínio do hexagonal, do post 02.)

main.py (FastAPI) (a mesma API) ┌──────┴──────┐ ▼ ▼ ⚡ Azure Functions λ AWS Lambda (onde eu comecei) (pra onde a série vai)

Azure Functions: onde tudo começou pra mim

Foi o primeiro palco da minha carreira. E hoje a integração é ainda mais direta: a Azure Functions fala ASGI (o protocolo do FastAPI) nativamente. Três linhas e a API inteira da outra aba vira serverless:

function_app.py — a API inteira num wrapper

import azure.functions as func
from main import app as api_fastapi   # a MESMA API da aba Python

app = func.AsgiFunctionApp(
    app=api_fastapi,
    http_auth_level=func.AuthLevel.ANONYMOUS)

Local é func start. E no estágio o deploy nem era manual: saía por esteira no Azure Pipelines — commit na branch, pipeline roda, função no ar. Ver aquela URL pública respondendo o nosso JSON depois do pipeline ficar verde foi o momento "caraca, isso é real".

AWS Lambda: a mesma API, outro palco

Na AWS, o adaptador se chama Mangum — ele traduz o event da Lambda pro formato que o FastAPI entende. De novo, a lógica não muda:

handler.py — pip install mangum

from mangum import Mangum
from main import app   # a MESMA API, de novo

handler = Mangum(app)

Percebeu o padrão? Azure e AWS viraram detalhe. A API é uma só; cada nuvem ganha só um arquivinho de adaptação na borda.

E o currículo? Lembra que arquivo local some quando a função desliga. Na nuvem, o endpoint de upload grava no storage — S3 na AWS, Blob na Azure:

curriculos_s3.py — mesmo desenho, storage de verdade

import boto3

s3 = boto3.client("s3")

def salvar_curriculo(usuario, curriculo_pdf, bucket="curriculos-rh"):
    chave = f"{usuario['id']}-curriculo.pdf"
    s3.put_object(Bucket=bucket, Key=chave, Body=curriculo_pdf)
    return chave

E o "aC" do IaC: a infra escrita em arquivo

Aqui entra a parte que muda o jogo. Em vez de criar a função clicando no console, você declara ela num arquivo. Este Terraform diz "existe uma Lambda com esse código" — e ela passa a existir:

main.tf — a função existe porque este arquivo existe

resource "aws_lambda_function" "api_curriculos" {
  function_name = "api-curriculos"
  runtime       = "python3.12"
  handler       = "handler.handler"   # o Mangum da API
  filename      = "lambda.zip"
  role          = aws_iam_role.lambda_role.arn
}

resource "aws_s3_bucket" "curriculos" {
  bucket = "curriculos-rh"
}

terraform apply e está no ar. Precisa recriar tudo num ambiente novo? Mesmo comando. Alguém pergunta "como está configurada a produção?" — está no Git, com histórico de quem mudou o quê. Isso é o que "infra como código" quer dizer na prática.

O erro clássico de quem começa: criar metade no console ("é só um teste...") e metade no código. Três meses depois ninguém sabe o que existe, o Terraform quer destruir coisas que "sempre existiram", e o ambiente de teste nunca fica igual ao de produção. Escolheu IaC? Tudo pelo código — o console vira só vitrine pra olhar.

A dupla em números

✅ O que a dupla te dá

  • Velocidade com segurança: a lógica é simples de escrever E a infra é reproduzível.
  • Custo quase zero pra começar: serverless cobra por execução — projeto pequeno roda de graça.
  • Portabilidade real: função pura roda na Azure, na AWS ou no seu terminal.
  • Ambiente novo em minutos: apply e pronto, sem checklist manual.

⚠️ Pontos de atenção

  • Cold start: função parada demora uns instantes pra acordar. Pra RH interno, ok; pra checkout, avalie.
  • Estado não mora na função: tudo que precisa sobreviver vai pra storage ou banco.
  • Terraform tem curva: state, providers, plan... reserve uma tarde pra entender antes do primeiro apply.
  • Limites de execução: Lambda tem teto de tempo e memória — processamento pesado pede outro desenho.
Quando usar a dupla: APIs pequenas e médias, automações agendadas (relatório toda segunda às 8h), processamento de upload (chegou currículo → valida → notifica RH), webhooks e integrações. Se a tarefa é "recebe, processa, responde" — é aqui que ela fica simples, barata e no ar.
