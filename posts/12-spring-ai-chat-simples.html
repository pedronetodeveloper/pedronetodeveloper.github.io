Spring AI do zero: um chat simples com qualquer LLM

Pedro Neto • 15 out 2026 • 10 min de leitura

Por que você deveria entender isso?

Todo mundo já usou um chat de IA. Pouca gente sabe que, no Java, colocar um desses dentro da sua API leva uma dependência, duas linhas de configuração e um controller.

Neste post a gente faz exatamente isso: um endpoint /chat que recebe uma pergunta, manda pra uma LLM usando sua chave de API e devolve a resposta. Sem framework mágico, sem front, sem banco.

E o melhor: o mesmo código funciona com OpenAI, Groq, OpenRouter ou um modelo rodando no seu notebook. Só muda a configuração.

🌱 O que é Spring AI (em uma frase)

Spring AI é o “Spring Data das LLMs”: você conversa com uma interface só, e o provedor de IA vira detalhe de configuração.

Sem Spring AI, você teria que montar na mão a requisição HTTP pra API do provedor, serializar o JSON, tratar erro e ler a resposta. E se trocasse de provedor, reescrevia tudo.

Com Spring AI, você usa o ChatClient. Ele fala com o provedor que estiver configurado no application.properties. O seu código não sabe (e nem precisa saber) se do outro lado está o GPT, o Llama ou o Gemini.

🔑 “Via tokens”: as duas palavras que confundem

Quando alguém fala “consumir uma LLM via token”, pode estar falando de duas coisas diferentes. Vale separar antes de escrever código:

TermoO que éOnde aparece
Chave de API (API key / token de acesso)A “senha” que identifica você no provedor. Sem ela, a API devolve 401.No application.properties, lida de uma variável de ambiente.
Tokens (de texto)Pedaços de palavra que o modelo lê e escreve. É por eles que você paga.Na resposta da API, no campo de uso (usage).

Regra prática: em português, 1 token ≈ 3 a 4 caracteres. Uma pergunta curta e uma resposta de um parágrafo ficam na casa das centenas de tokens, ou seja, centavos (ou de graça, nos planos gratuitos).

📦 Passo 1: criar o projeto

Vai no start.spring.io e escolhe:

  • Project: Maven · Language: Java 21 · Spring Boot: a versão estável mais recente
  • Dependencies: Spring Web e OpenAI (fica na seção “AI”)

Gera, descompacta e abre no IntelliJ. No pom.xml, o que importa são estas partes (o Initializr já coloca pra você):

pom.xml

<properties>
    <java.version>21</java.version>
    <spring-ai.version>1.0.0</spring-ai.version> <!-- use a que o Initializr gerar -->
</properties>

<dependencies>
    <dependency>
        <groupId>org.springframework.boot</groupId>
        <artifactId>spring-boot-starter-web</artifactId>
    </dependency>
    <dependency>
        <groupId>org.springframework.ai</groupId>
        <artifactId>spring-ai-starter-model-openai</artifactId>
    </dependency>
</dependencies>

<dependencyManagement>
    <dependencies>
        <dependency>
            <groupId>org.springframework.ai</groupId>
            <artifactId>spring-ai-bom</artifactId>
            <version>${spring-ai.version}</version>
            <type>pom</type>
            <scope>import</scope>
        </dependency>
    </dependencies>
</dependencyManagement>

O BOM (spring-ai-bom) alinha as versões de todos os módulos do Spring AI. Por isso o starter não tem <version>.

⚙️ Passo 2: configurar a chave

Pegue uma chave no painel do provedor (OpenAI, Groq, OpenRouter...) e exporte como variável de ambiente:

# Linux / macOS
export OPENAI_API_KEY="sk-...sua-chave..."

# Windows (PowerShell)
$env:OPENAI_API_KEY="sk-...sua-chave..."

No projeto, o application.properties só aponta pra essa variável e escolhe o modelo:

src/main/resources/application.properties

spring.ai.openai.api-key=${OPENAI_API_KEY}
spring.ai.openai.chat.options.model=gpt-4o-mini
spring.ai.openai.chat.options.temperature=0.7
  • model: qual LLM usar. Modelos “mini” são baratos e mais que suficientes pra aprender.
  • temperature: criatividade. Perto de 0 = respostas mais previsíveis; perto de 1 = mais variadas.
Erro que não pode acontecer: colar a chave direto no application.properties e dar commit. Bots varrem o GitHub atrás de chaves expostas em minutos, e a conta é sua. Sempre ${VARIAVEL}, e a chave fica só na sua máquina (ou no cofre de segredos do deploy).

💬 Passo 3: o controller do chat

O ChatClient é o único objeto que você precisa conhecer: monta o prompt, chama a LLM e devolve o texto.

O starter já registra um ChatClient.Builder configurado com a sua chave. A gente só pede ele no construtor e monta o client:

ChatController.java

package dev.neto.chat;

import org.springframework.ai.chat.client.ChatClient;
import org.springframework.web.bind.annotation.*;

@RestController
@RequestMapping("/chat")
public class ChatController {

    private final ChatClient chatClient;

    public ChatController(ChatClient.Builder builder) {
        this.chatClient = builder
            .defaultSystem("Você é um assistente que responde em português, de forma curta e direta.")
            .build();
    }

    @GetMapping
    public String perguntar(@RequestParam String mensagem) {
        return chatClient.prompt()
            .user(mensagem)      // o que o usuário perguntou
            .call()              // chama a LLM (espera a resposta inteira)
            .content();          // pega só o texto da resposta
    }
}

Lendo de cima pra baixo:

  • defaultSystem(...): o system prompt, a “personalidade” do assistente. Vale pra todas as perguntas.
  • prompt().user(mensagem): a pergunta do usuário.
  • call(): faz a chamada e espera a resposta completa.
  • content(): devolve só a String da resposta.

É isso. Não tem classe de configuração, não tem cliente HTTP, não tem DTO de request.

./mvnw spring-boot:run

Algo assim volta:

Um record é um tipo de classe imutável, criado pra carregar dados.
O Java gera sozinho construtor, getters, equals, hashCode e toString.
Se você está com pressa: também dá pra abrir a URL direto no navegador. É um GET, então funciona sem Postman.

🔄 Trocando de LLM sem mexer no Java

Aqui está o pulo do gato. Muitos provedores expõem uma API compatível com a da OpenAI. Então o mesmo starter conversa com eles: basta trocar a URL base, a chave e o nome do modelo.

application.properties — Groq, com plano gratuito

spring.ai.openai.base-url=https://api.groq.com/openai
spring.ai.openai.api-key=${GROQ_API_KEY}
spring.ai.openai.chat.options.model=llama-3.3-70b-versatile

application.properties — OpenRouter, vários modelos numa chave só

spring.ai.openai.base-url=https://openrouter.ai/api
spring.ai.openai.api-key=${OPENROUTER_API_KEY}
spring.ai.openai.chat.options.model=meta-llama/llama-3.3-70b-instruct

Quer rodar sem chave nenhuma, no seu notebook? Instala o Ollama, baixa um modelo (ollama pull llama3.2) e troca o starter no pom.xml por spring-ai-starter-model-ollama:

application.properties — Ollama local

spring.ai.ollama.base-url=http://localhost:11434
spring.ai.ollama.chat.options.model=llama3.2

Repara: o ChatController não mudou uma linha em nenhum dos casos.

Quando usar cada um: pra aprender sem gastar, Groq (plano gratuito) ou Ollama (local). Pra comparar modelos, OpenRouter. Pra produção, o provedor que sua empresa já contratou, com a chave no cofre de segredos.

📊 Bônus: quantos tokens eu gastei?

Lembra dos tokens de texto? Dá pra ler o consumo de cada chamada. Em vez de content(), pede a chatResponse() inteira:

ChatController.java — dentro da mesma classe

import org.springframework.ai.chat.model.ChatResponse;
import org.springframework.ai.chat.metadata.Usage;

public record RespostaChat(String resposta, Integer tokensPergunta,
                           Integer tokensResposta, Integer tokensTotal) {}

@GetMapping("/detalhado")
public RespostaChat perguntarDetalhado(@RequestParam String mensagem) {
    ChatResponse resposta = chatClient.prompt()
        .user(mensagem)
        .call()
        .chatResponse();

    Usage uso = resposta.getMetadata().getUsage();
    return new RespostaChat(
        resposta.getResult().getOutput().getText(),
        uso.getPromptTokens(),       // tokens que você mandou
        uso.getCompletionTokens(),   // tokens que a LLM escreveu
        uso.getTotalTokens()         // é isso que vira cobrança
    );
}
{
  "resposta": "Um record é um tipo de classe imutável...",
  "tokensPergunta": 31,
  "tokensResposta": 42,
  "tokensTotal": 73
}

Repara que o system prompt também conta como token de pergunta, em toda chamada. System prompt gigante = conta gigante.

⚠️ Os erros que você vai ver (e o que significam)

ErroCausa mais comumCorreção
401 UnauthorizedChave errada ou variável de ambiente não exportada no terminal que subiu a app.Confira com echo $OPENAI_API_KEY e suba a app de novo no mesmo terminal.
429 Too Many RequestsLimite do plano estourado ou conta sem crédito.Espere um pouco, ou adicione crédito, ou troque pra Groq/Ollama.
404 / modelo não encontradoNome do modelo não existe naquele provedor.Copie o nome exato da página de modelos do provedor.
404 na URLbase-url com /v1 no final. O Spring AI já adiciona /v1/chat/completions.Deixe a URL base sem o /v1.
Erro que EU cometi: exportei a chave num terminal e rodei a aplicação pelo botão Run do IntelliJ. O IntelliJ não enxerga variáveis de um terminal aberto à parte, então tomei 401 e perdi meia hora. Na IDE, a variável vai em Run → Edit Configurations → Environment variables.

A história por trás desse post

Minha primeira integração com LLM foi um cliente HTTP escrito na mão: montava o JSON, tratava cada erro, parseava a resposta. Funcionava, mas era um código que ninguém queria manter, e trocar de provedor significava reescrever tudo.

Quando migrei pro Spring AI, aquele arquivo de mais de cem linhas virou o ChatController que você viu aqui. Foi aí que caiu a ficha: IA no backend é integração, e integração o Spring resolve há anos.

Conclusão

Se você sair daqui com uma frase, que seja essa: a chave fica na variável de ambiente, o provedor fica no application.properties, e o seu código só conhece o ChatClient. O resto (stream, memória de conversa, ferramentas) é construído em cima disso.
