Fundação em Python: o essencial pra sair automatizando

Pedro Neto • 15 jul 2026 • 14 min de leitura

Por que Python?

Python foi a primeira linguagem que usei profissionalmente — e é a que eu recomendo pra qualquer pessoa começando na TI. O motivo é simples: a distância entre "aprendi o conceito" e "resolvi um problema real" é a menor que existe. Não precisa de framework, não precisa de setup complicado. Um arquivo .py e você já está automatizando coisa do seu dia.

Por isso este post é diferente dos tutoriais de sempre: sem framework, só Python puro — e no fim de cada seção, em vez de exemplo de banco de dados, uma automação de verdade usando o que você acabou de aprender. Todo código daqui foi testado: copia e roda.

🧱 Variáveis e tipos: simples do jeito certo

Em Python, variável não tem tipo declarado — o valor é que tem tipo. Você escreve menos, mas precisa saber o que está guardando.
nome = "Pedro"        # str
idade = 25            # int
altura = 1.75         # float
ativo = True          # bool (com T maiúsculo!)

# f-string: o jeito moderno de montar texto
mensagem = f"{nome} tem {idade} anos"

TAXA = 0.05           # convenção: MAIÚSCULO = "não mexa"
  • Sem int x, sem final — o Python descobre o tipo pelo valor. Vindo do Java, a sensação é de estar esquecendo algo. Não está.
  • f-string sempre — f"texto {variavel}" resolve 99% da formatação. Concatenar com + é coisa do passado.
  • Constante é convenção — nome em maiúsculo avisa "não reatribua". O Python não impede, o combinado protege.
🤖 na prática — automação com isso aqui

Só com variável e f-string você já monta a mensagem de log de um backup:

from datetime import date

projeto = "blog-do-neto"
hoje = date.today()
print(f"[backup] {projeto} salvo em {hoje:%d/%m/%Y}")
# [backup] blog-do-neto salvo em 15/07/2026

🔀 Condições e loops: o fluxo do script

if decide, for percorre, while repete até a condição virar. E em Python, a indentação É o bloco — não é estética, é sintaxe.
nota = 85
if nota >= 90:
    conceito = "A"
elif nota >= 70:
    conceito = "B"
else:
    conceito = "C"

# for com range: quando você sabe quantas vezes
for i in range(3):
    print(f"tentativa {i + 1}")

# for direto na coleção (o mais comum em Python)
techs = ["Java", "Python", "AWS"]
for i, tech in enumerate(techs, start=1):
    print(i, tech)

# while: repete enquanto a condição vale
saldo = 27
while saldo > 0:
    saldo -= 10
O erro que pega TODO iniciante: indentação errada. Um espaço fora do lugar e o código muda de significado ou lança IndentationError. Configura seu editor pra 4 espaços e nunca mais pensa nisso.
🤖 na prática — automação com isso aqui

Um for + if e você tem um fiscal de arquivos gigantes na sua pasta:

from pathlib import Path

for arquivo in Path("downloads").iterdir():
    tamanho_mb = arquivo.stat().st_size / 1_000_000
    if tamanho_mb > 100:
        print(f"⚠️ {arquivo.name} está com {tamanho_mb:.0f} MB")

🧰 Funções: o bloco que você reusa

Função é como você para de copiar e colar código. Se você escreveu a mesma lógica duas vezes, era pra ser uma função.
def calcular_desconto(preco, percentual=10):
    return preco * (1 - percentual / 100)

calcular_desconto(200)                       # 180.0 — usa o padrão
calcular_desconto(200, 25)                   # 150.0
calcular_desconto(preco=200, percentual=5)   # 190.0 — nomeado, mais legível
  • Parâmetro com padrão (percentual=10) — quem chama só informa o que foge do comum.
  • Argumento nomeado — em chamada com vários parâmetros, nomear deixa o código autoexplicativo.
  • Função pequena com nome claro vale mais que comentário. calcular_desconto dispensa explicação.
🤖 na prática — automação com isso aqui

Uma função que decide o destino de cada arquivo — guarda ela, vamos usar na automação final:

def destino_por_extensao(arquivo):
    pastas = {".pdf": "documentos", ".png": "imagens", ".zip": "compactados"}
    return pastas.get(arquivo.suffix, "outros")   # sem match? vai pra "outros"

📚 Coleções: list, dict e set

list guarda em ordem, dict busca por chave, set garante que não repete. É o mesmo raciocínio do List/Map/Set do Java — com muito menos cerimônia.
techs = ["Java", "Python", "AWS", "Python"]   # list: ordem, aceita repetição
unicas = set(techs)                            # set: {"Java", "Python", "AWS"}

horas = {"Java": 120, "Python": 80}            # dict: chave -> valor
horas["AWS"] = 40                              # adiciona na hora, sem drama

# list comprehension: transformar coleção em UMA linha
maiusculas = [t.upper() for t in techs if t != "AWS"]
# ['JAVA', 'PYTHON', 'PYTHON']
List comprehension é o "stream" do Python: filtra e transforma numa linha só, sem map().filter().collect(). Mas a regra é a mesma do Java: se ficou difícil de ler, volta pro for normal.
🤖 na prática — automação com isso aqui

Um dict e você tem um relatório do que está entulhando sua pasta:

from pathlib import Path

contagem = {}
for arquivo in Path("downloads").iterdir():
    ext = arquivo.suffix or "sem extensão"
    contagem[ext] = contagem.get(ext, 0) + 1

print(contagem)   # {'.pdf': 12, '.png': 34, '.zip': 5, ...}

🧯 Erros: try/except sem drama

try/except é o try/catch do Python. A regra continua a mesma: capture só o que você tem como tratar — e nunca em silêncio.
# erro esperado: entrada do usuário
entrada = "abc"
try:
    quantidade = int(entrada)
except ValueError:
    print("Digite um número válido")

# erro esperado: arquivo que pode não existir
from pathlib import Path
try:
    config = Path("config.txt").read_text()
except FileNotFoundError:
    config = "config padrão"   # plano B claro e documentado
O primo python do catch vazio: except: pelado (ou except Exception: pass). Engole TODO erro — até o Ctrl+C que você aperta desesperado. Sempre nomeie a exceção que espera: except ValueError:, except FileNotFoundError:.
Quando usar: try/except pra situações que você espera que possam falhar — entrada do usuário, arquivo ausente, rede. Erro de lógica do SEU código não se esconde com except: se deixa estourar, se lê o traceback e se conserta.

📂 Arquivos e a automação final

pathlib é o jeito moderno de mexer com arquivos: caminho vira objeto, e ler/escrever vira uma linha.
from pathlib import Path

arquivo = Path("notas.txt")
arquivo.write_text("aprender python\n")       # escreve
conteudo = arquivo.read_text()                # lê
existe = arquivo.exists()                     # confere
for item in Path("downloads").iterdir():      # percorre pasta
    print(item.name, item.suffix)

E agora, o gran finale: juntando TUDO que você viu — variáveis, for, if, função, dict, pathlib — no script que eu mais uso na vida real. Ele organiza sua pasta de downloads em subpastas por tipo de arquivo:

organizar_downloads.py — testado: rodou, organizou

from pathlib import Path
import shutil

PASTAS = {
    ".pdf": "documentos",
    ".png": "imagens",
    ".jpg": "imagens",
    ".zip": "compactados",
}

def organizar(pasta="downloads"):
    origem = Path(pasta)
    movidos = 0
    for arquivo in list(origem.iterdir()):
        if arquivo.is_file():
            destino = origem / PASTAS.get(arquivo.suffix.lower(), "outros")
            destino.mkdir(exist_ok=True)
            shutil.move(str(arquivo), str(destino / arquivo.name))
            movidos += 1
    print(f"✅ {movidos} arquivos organizados")

organizar()

Vinte e poucas linhas, zero dependência externa, e um problema real resolvido. Isso é o espírito do Python: o caminho mais curto entre você e o problema resolvido.

Quando usar Python puro (sem framework): automações de arquivos e pastas, scripts de rotina, processamento de texto e dados pequenos, ferramentas de linha de comando pro seu time. Quando virar API pra outras pessoas consumirem — aí sim entra framework, e é exatamente o assunto do próximo post.
